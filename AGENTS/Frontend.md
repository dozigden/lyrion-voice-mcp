# Frontend Guidance

- Use Vue 3, TypeScript, Vite, Pinia, and Vue Router.
- Organise feature code beneath `src/features/<feature>`; use `src/shared` only for genuinely cross-feature primitives.
- Keep API wrappers strongly typed and scoped to their route namespace.
- Components own local form/draft state; Pinia stores own shared feature state and asynchronous operations.
- Treat backend contracts as authoritative. Do not add speculative client normalisation without an observed failure mode.
- Keep shared/global CSS in `src/style.css` or `src/shared/styles`; keep page/component-specific CSS in scoped Vue styles.
- Prefer semantic HTML, labelled controls, keyboard access, and responsive layouts.
- Scheduled-job cards expose interval or daily-time controls only when the backend returns editable configuration metadata. Retain accessible names without visible interval or daily-time labels. Keep retention cards read-only, use an explicit Save action, reload the saved card so cron and next-run state are authoritative, and keep Run now independent of configured or effective schedule availability.
- Show only Disabled or Unavailable scheduled-job statuses beside their titles; omit the normal Enabled status. Keep Run now in the amber heading. Use compact, wrapping configuration controls with Save beside the editable value. In the labelled metadata below, group Next run above Cron expression on the left and Current job above Last job on the right. Omit time zone and last-evaluated fields from the cards.
- Do not use nested ternaries or `$event` expressions in templates; use named handlers and explicit branching.
- Keep operational warnings concise. The trusted-LAN warning must remain visible wherever connection details are presented.
- Tool-log filters apply immediately through URL-backed state without an Apply action. Prefix tool names in list rows and detail headings with the same dependency-free, decorative tool icon, retaining a neutral icon for unknown historical tools. Rows show the API-provided request summary beneath the tool name when available, limited to two lines with the full bounded text in a title attribute. Omit duration and successful outcomes from rows; show other outcomes so successful entries remain compact. Do not fetch individual call details to populate list rows.
- Tool-call details use persisted reference snapshots to present browse, play and queue-addition arguments with captured names and context. Preserve request order and every opaque reference, label missing metadata honestly, show up to five items horizontally and longer lists vertically, and fall back to the recorded arguments for older or truncated snapshots. Never resolve historical references live.
- The tool log is the landing page, without a setup diversion. Use independently scrolling list/detail panes, URL-backed selection and filters, and a narrow-screen return to the list. Do not automatically refresh the log or infer related calls.
- Render all current MCP tool results as recorded labelled data by default, retaining a Raw JSON tab and honest fallback for unknown, invalid, missing or truncated recordings. Separate result content from arguments with the shared amber heading bands, including search's exact artist result, and finish details with an amber Other section for residual content and diagnostics. Keep distinct response messages and partial outcomes visible. Never resolve historical references through live calls.
- Support current tool result formats only; older formats use the Raw JSON fallback, without compatibility adapters. An absent or null SDK `structuredContent` is normal for text-only results and must not itself trigger an unsupported-format warning.
- Present lists of up to five items horizontally, wrapping on narrow screens; longer lists vertically. Search's main tracks are always vertical. Use full-width amber heading bands and aubergine selection, with 16px base text and at least 14px metadata.
- System contains overview, jobs, schedules and errors. Only compact catalogue/index state belongs in the main header; both link to System. Keep Licences at the far right. The tool log deliberately has no retention text.
- Keep System overview connections compact, with server identity and version grouped and the trusted-LAN notice beside the MCP endpoint. Maintenance sections use equal full-width amber headings with their Rebuild actions in the heading at every screen width; keep statistics and job links underneath. Distinguish readiness, work in progress, retained-data warnings, and unavailable states with labelled status dots. Group statuses closely with their section headings, leaving only maintenance actions aligned to the right.
- Search-observation frontend routes and state have been removed; its backend API remains available.
- Decode API data with feature-owned schemas built from the shared runtime decoders; validate all consumed fields, nested collections and required nullable values. Use the shared HTTP/error boundary, without unchecked JSON casts or speculative normalisation.
- Feature stores own remote state and mutations. Pair AbortController cancellation with identity guards so superseded or unmounted requests cannot publish stale data. Keep local filters and schedule drafts in components; run-now must preserve unsaved drafts.
- Keep `/licences` backed by the committed static `/third-party-licenses` mirror so disclosure remains available without the API or an external network request.
